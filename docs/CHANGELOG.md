# Changelog

All notable changes to Confluent are documented here.

## Format

Each entry follows: `date | what changed | why it matters`

Releases follow [Semantic Versioning](https://semver.org). Categories per release:
- **Added** — new features
- **Changed** — changes to existing behavior
- **Fixed** — bug fixes
- **Removed** — removed features or behavior

- 2026-06-04 | Trade View page (#50) — `TradeViewPage` replaces stub; fetches trade fresh on every navigation via `trade:get`; renders a header with a back arrow (`goBack()` on the updated navigation store, which now tracks `previousPage` and exposes `goBack`), the trade title, and Edit/Delete actions; `TradeDetailContent` (new `src/renderer/src/components/trade-view/trade-detail-content.tsx`) holds the 3-column field grid, notes, and 3-state screenshot block (loading/found/not-found) — also consumed by the refactored `TradeDetailDialog` to eliminate duplication; `StrategyRulesSummary` (collapsible, collapsed by default) loads the setup type's strategy rules via `strategy-rules:get` and renders them read-only, or shows "No rules defined" if none exist; `AiReviewPlaceholder` shows a static stub message; `DeleteTradeDialog` uses the existing `Dialog` primitive for a confirmation step before calling `trade:delete` and navigating back; `TradeEntryForm` generalized with `mode / initialTrade / onSaved / onCancel` props — in edit mode pre-fills all fields from the trade (ISO → `datetime-local`), calls `trade:update`, and hides the screenshot section (screenshot editing deferred); invalid/missing trade id shows an error state with a "Back to Dashboard" link | Completes the V2 Improved UI checklist — Trade View is now the single destination for full trade detail, inline editing, and deletion from anywhere in the app (Dashboard recent trades, calendar day drill-down)
- 2026-06-04 | Dashboard home page (#49) — `DashboardPage` replaces placeholder; stats row across the top (`StatsPanel` — all-time win rate, total trades, total P&L); `CalendarGrid` for the current month with per-day trade count, net P&L, and green/red/neutral color coding; `RecentTradesList` (new `src/renderer/src/components/dashboard/recent-trades-list.tsx`) — compact 5-column table (date, instrument, direction, outcome badge, P&L) showing the 10 most recent trades; clicking a calendar day filters the list to that day's trades with a "Show recent" clear control; clicking any row navigates to Trade View via `navigateToTrade`; all trades fetched on mount via a single `trade:list` call with month filtering derived client-side; no new IPC handlers, stores, or schema changes | Completes the V2 Dashboard checklist item — the app's default landing page now gives an at-a-glance view of all-time performance, the current month's calendar, and recent trade history

- 2026-06-03 | Knowledge base editor UI (#47) — `KnowledgeBasePage` replaces placeholder; `KbList` (filter by category or setup type, entry rows showing title/category/setup/date, full empty state with guidance text), `KbEditor` (full-page create/edit form with title, category Select, setup-type Select, multiline content textarea; unsaved-changes guard on Back; delete with confirmation dialog), `KbDeleteDialog`, `kb-form-schema` zod schema; list + editor switch via local view state — no changes to global navigation store (`src/renderer/src/pages/knowledge-base-page.tsx`, `src/renderer/src/components/knowledge-base/`) | Completes the knowledge base feature end-to-end — users can now write and organize strategy notes by category and setup type, ready for AI post-trade review to consume
- 2026-06-02 | Import Review Queue UI (#46) — `ImportReviewPage`, `PendingImportRow`, `ConfirmRejectDialog`, `useImportReviewStore` (`src/renderer/src/pages/import-review-page.tsx`, `src/renderer/src/components/import-review/`, `src/renderer/src/stores/import-review-store.ts`); sidebar "Import Review" nav item between Dashboard and Strategy Rules with count badge; each pending import card shows read-only CSV data (instrument, direction, prices, times, quantity, P&L, outcome) alongside editable fields (session Select, setup type Select, notes Textarea, screenshot attach) that save on blur/change to `pending_imports` so partial work survives a reload; per-row Confirm button (disabled until session + setup type both set) and Reject button (confirmation dialog); bulk Confirm and Reject for selected rows — incomplete rows skipped on bulk confirm with partial-success toast; empty state with inline CSV import trigger; `'import-review'` added to `Page` union in navigation store | Completes the Tradovate auto-import feature end-to-end — users can now import a Tradovate CSV, annotate each trade in the review queue, and confirm them into the main trade log
- 2026-06-02 | CSV import flow — file dialog, parse, and enqueue (#45) — `import:from-csv` IPC handler opens a native Electron file dialog (`.csv` filter), reads the selected Tradovate export, parses it via `parseTradovateCsv`, and bulk-inserts results into `pending_imports` via `handleImportEnqueue`; returns `ImportFromCsvResult` envelope: `cancelled` flag, `filePath`, `enqueuedCount`, `parseErrors` (row + reason only, `raw` omitted), and parser `summary`; user cancel returns a success envelope with `cancelled: true` so the renderer never shows a spurious error toast; `fromCsv()` added to `window.api.import` preload namespace; `ImportFromCsvResult` interface and `import:from-csv` channel added to `src/shared/ipc-types.ts`; 7 unit tests covering happy path, empty CSV, all-invalid, partial success, parser throw, raw-field stripping, and DB error propagation | Closes the gap between the parser/queue data layer and a usable import trigger — the renderer can now call `window.api.import.fromCsv()` to drive the full import pipeline; review queue UI (#46) is all that remains for end-to-end Tradovate import
